# F4: рынок одного актива

Точка входа: `marketsim.sim.api.run(config, seed, out_dir)`. Результат — каталог с шестью таблицами
и `meta.json`, который читает `marketsim.sim.log_schema.load_run`. Торговля идёт только через K1
`Gateway`; интерфейсы K1–K4 и тесты контрактов не изменены.

## Запуск

Из корня репозитория после установки `.[dev]`:

```bash
python -m marketsim.experiments.run configs/f4_pilot.yaml --out runs/f4/review-v3/pilot
```

Для проверки одного прогона добавьте `--limit 1`. Каталог эксперимента должен быть новым:
готовые результаты не перезаписываются и автоматически не пропускаются. `--workers N` запускает
прогоны в N процессах: прогоны независимы, поэтому логи и `summary.csv` те же, что при последовательном
запуске (различается только время в metadata). Возобновление прерванной сетки относится к F7.
Для C++ замените `exchange_backend` на `cpp` после установки `cpp/`.

Одновременно отправляется не более N задач. После ошибки новые прогоны не запускаются;
уже выполняющиеся завершаются, их успешные результаты попадают в `summary.csv`, затем
исходная ошибка передаётся вызывающему коду. Принудительной остановки активного прогона нет.

Конфиги `f4_e1.yaml`, `f4_e2.yaml`, `f4_e3.yaml` запускаются той же командой с отдельным `--out`;
их варианты с целевой позицией — `f4_pilot_target.yaml`, `f4_e1_target.yaml`, `f4_e2_target.yaml`,
`f4_e3_target.yaml` (те же сетки и seeds). Результаты 12.11.2026 — в `runs/f4/v4/<имя без f4_>`.
В каталоге сохраняются исходная конфигурация `experiment.json`, логи и накопительная `summary.csv`.
Notebook `notebooks/03_experiments.ipynb` читает эти результаты; каталог `runs/` не коммитится.
Для графиков notebook установите optional-зависимости `.[notebooks]` (или только `matplotlib`,
если notebook запускается в уже подготовленном Jupyter). Для CLI и симуляции matplotlib не нужен.

## Границы F4

- `graph: single_asset` — явно выбранный синтетический рынок, без графа K2; тикер и стартовая цена
  находятся в `agents`. Загрузка цепочки из `pilot.yaml` относится к F5 и пока отвергается.
- `external: flat`, `use_market_index: false`. Постоянный fixture загружается через API данных;
  его постоянные уровни продолжаются на всю длину прогона. Исторические данные не нужны.
- Сессия имеет длину 1. Очередь упорядочена по времени и порядку добавления. Сначала выполняется
  открытие первой сессии, начальные котировки маркет-мейкеров и снимок; инвесторы просыпаются
  через экспоненциальные интервалы. События с `t >= n_sessions` не исполняются.
- GTD истекает событием планировщика; перед следующим решением старые заявки агента снимаются.
  Перед завершением записывается последний снимок, затем оставшиеся заявки снимаются,
  чтобы зарезервированные ресурсы вернулись владельцам.

## Устройство реализации

- `sim/settings.py` проверяет свободную секцию `agents` контракта K4.
- `sim/population.py` создаёт группы инвесторов и распределяет целочисленные ресурсы.
- `sim/scheduler.py` содержит очередь `(time, seq, event)` с устойчивым порядком равных времён.
- `agents/strategies.py` и `agents/herding.py` реализуют собственные сигналы, заявки и знакомства.
- `sim/engine.py` связывает события, агентов и шлюз. Это единственный потребитель `drain_fills()`.
- `sim/recorder.py` обновляет исполнения обеих сторон и записывает все таблицы K3 через `write_table`.
- `experiments/run.py` запускает последовательную сетку; `diagnostics.py` читает только лог K3.

Регрессионные тесты находятся в `tests/sim/`, `tests/agents/`, `tests/experiments/`.
Они проверяют очередь и GTD, точное сохранение ресурсов, детерминизм, ограничения заявок,
нехватку ресурсов, стратификацию фондов, крайние параметры и совпадение Python/C++.

## Параметры агентов

Неизвестные ключи и некорректные значения отвергаются до создания файлов прогона.
Полный набор значений по умолчанию — `sim/settings.py`; разрешённые параметры:

| Группа | Поля |
|---|---|
| Рынок | `ticker`, `initial_price_ticks` |
| Участники | `valuers`, `trend`, `noise`, `market_makers_per_asset`, `n_funds` |
| Ресурсы инвесторов | `concentration`, `total_cash_cents`, `total_shares` |
| Ресурсы маркет-мейкеров (на каждого) | `market_maker_cash_cents`, `market_maker_shares` |
| Сигналы | `valuation_std`, `gamma`, `trend_lookback`, `trend_scale` |
| Пробуждения | `decision_rate`, `market_maker_rate` (в среднем решений на сессию) |
| Заявки | `rho`, `threshold`, `aggressive_prob`, `protection_fraction`, `passive_offset_ticks`, `tif`, `order_lifetime` |
| Маркет-мейкер | `market_maker_spread_ticks`, `market_maker_qty`, `inventory_skew_ticks` |
| Стадность | `herding: {h, neighbors, ttl, followers, h_std}`; `followers` и `h_std` — разная подверженность стадности (F5, по умолчанию у всех ровно h) |
| Проверки и эксперименты | `debug`, `ablation` |

Оценщик хранит постоянную индивидуальную оценку `P0 * (1 + e)`, где `e` нормально распределена
с заданным `valuation_std` и ограничена диапазоном [-0.9, 0.9]. Трендовый агент сравнивает
текущую цену с последним снимком не позже `now - trend_lookback`; до появления такой истории
используется стартовая цена. Шумовой агент выбирает сигнал равномерно из [-1, 1].

Сеть знакомств направленная, фиксированная на прогон, без самого себя и повторных соседей.
Соседи публикуют направление принятой биржей заявки (-1/+1). Если модуль сигнала не превышает порог,
`rho=0`, ресурсов не хватило или шлюз отклонил заявку, публикуется 0.
Публикация не требует исполнения: принятая пассивная или IOC-заявка могла не найти контрагента.
Неопубликованный или просроченный сигнал считается нулём; знаменатель — полное число соседей.
Маркет-мейкеры в эту сеть не входят. В K3 `signals.final_signal` остаётся сигналом до ограничений
ресурсов; он может быть ненулевым, даже если опубликовано 0.

Сначала агент снимает старые заявки, затем получает собственный портфель и публичное состояние
рынка. При `abs(signal) > threshold` и `rho > 0` целевой объём:
`max(1, floor(rho * abs(signal) * wealth / price))`, затем он ограничивается доступными
деньгами по фактической лимитной цене или доступными акциями. Если ресурсов нет хотя бы
на одну акцию, заявки нет; `rho=0` по-прежнему отключает заявки. Минимальный лот может
превышать дробную цель `rho * abs(signal) * wealth`: это явное правило дискретной модели,
а не строгий предел доли капитала. Большие объёмы по-прежнему округляются вниз.
Агрессивная заявка — IOC с защитной ценой; пассивная размещается у лучшей цены своей стороны.
Покупка округляет защитную цену вниз, продажа вверх. Средняя цена двух котировок округляется
вниз до целого тика; при пустой стороне используется последняя сделка, затем стартовая цена.

Маркет-мейкер снимает обе свои заявки и размещает новые вокруг наблюдавшейся до снятия середины.
Избыток акций относительно стартового запаса понижает обе котировки. Его деньги и акции конечны.

Фонды — фиксированная подгруппа инвесторов, а не отдельная стратегия. Отбор стратифицирован
по типам: доли стратегий в фондах и retail совпадают, когда это допускает целое число участников.
Например, из 40 оценщиков, 20 трендовых и 20 шумовых выбираются 4, 2 и 2 фонда соответственно.
Для неделимых пропорций квоты округляются методом наибольших остатков; при равенстве остатков
приоритет: оценщики, трендовые, шумовые. Количества фондов каждого типа не зависят от seed или C.
Внутри каждого типа конкретные ID выбираются генератором прогона без повторов.
При изменении C меняется только распределение денег и акций между этими фондами и остальными.
Суммы, численность групп и набор стратегий сохраняются. Остатки целочисленного деления
раздаются по возрастанию ID. При точных квотах отклонение капитала типа от его пропорции
ограничено целочисленным распределением: менее одной денежной единицы или акции на участника.
Ресурсы маркет-мейкеров в C не входят.

## Воспроизводимость и проверки

`SeedSequence(seed)` создаёт отдельные потоки для групп, оценок, сети, пробуждений и решений.
У каждого агента свои потоки пробуждений и решений. Одинаковые конфиг и seed дают одинаковые
таблицы и `run_id`. Время запуска и фактическая длительность в metadata естественно различаются.
`wall_time_s` измеряет расчёт симуляции, без записи Parquet и его повторной проверки.

Текущая версия поведения — `f4-v3`: минимальный лот в одну акцию при допустимом сигнале,
стратифицированные фонды и публикация только допустимых торговых действий.
Версия и разрешённые значения параметров входят в идентификатор прогона;
изменение правил требует новой версии. Логи `f4-v1` и `f4-v2` сохранены локально
для истории; их численные результаты не относятся к текущей модели. Notebook использует `runs/f4/review-v3/`.

Сохранение денег и акций проверяется в начале и конце каждого прогона. `debug: true` добавляет
проверки после каждого решения и истечения. Начальные и конечные суммы записываются в metadata.
Данные сначала записываются во временный каталог и проверяются через `load_run`, затем
каталог переименовывается в окончательный. Существующий результат не перезаписывается.

## Ограничение статусов K1/K3

K1 не имеет кодов ручной отмены и истечения GTD, хотя K3 называет `orders.status` финальным статусом.
F4 не добавляет новые коды и не меняет контракт. В `orders.status` записывается последний статус
исполнения K1; количество исполненных акций обновляется и для пассивных заявок.
Отмена, истечение и снятие при завершении представлены событиями `order_cancelled`,
`order_expired`, `run_end_cancelled` с `order_id`, `agent`, `remaining_qty`.
Это указано и в `meta.order_status_semantics`. Для полной истории жизни заявки нужно читать
`orders` вместе с `events`. Потребителям K3 нельзя считать все строки `RESTING` активными
на конец прогона. Полноценное расширение enum требует согласования владельцев K1 и K3.

Отказы шлюза из-за ресурсов имеют `order_id = 0`; это не уникальный идентификатор строки лога.

## Протокол E0–E3, зафиксированный после пилота

Пилот E0: seeds 1–3, 30 сессий, прогрев 5, снимки через 0.02 сессии, 40 оценщиков,
20 трендовых, 20 шумовых, 1 маркет-мейкер, 8 фондов. Стадность h=0, C=0.5.
Пилот версии `f4-v3`: 1500–1650 сделок после прогрева, пустая сторона 0.00–0.40% времени,
средняя абсолютная ошибка относительно средней оценки 0.31–0.39%. Проверки ресурсов выполнены.
Наблюдений пилота недостаточно для вывода об исследовательских гипотезах.

Основные прогоны используют те же параметры времени и численности; seeds 1001–1030, без пересечения
с пилотом. Общие seeds разных вариантов используются для сравнения; одна единица статистики — прогон.
Для `f4-v3` 09.11.2026 перед полным повторным запуском оставлены те же сетки, seeds,
временные параметры и ресурсы. Сначала проверены пилот и 27 вариантов E1 на seeds 1001–1003;
эта проверка входит в последующие 270 E1, а не считается дополнительной независимой выборкой.
Правило минимального лота выбрано после обнаружения дефекта `f4-v2`; новая версия
не является независимым подтверждением гипотезы на ранее не просмотренных seeds.

| Эксперимент | Сетка | Прогоны |
|---|---|---|
| E1 | h = 0, 0.3, 0.6; C = 0.2, 0.5, 0.8 | 270 |
| E2 | при h=0.6, C=0.5: baseline, без стадности, без трендовых | 90 |
| E3 | при h=0.3, C=0.5: спред маркет-мейкера 4, 10, 30 тиков | 90 |

В E2 `ablation: no_herding` устанавливает эффективный h=0. `ablation: no_trend` заменяет правило
трендовых агентов на шумовое, сохраняя их ID, ресурсы, принадлежность фондам и интенсивность
пробуждений. Это контроль постоянной численности, а не удаление участников рынка.

`experiments/diagnostics.py` содержит первичные диагностические сводки по K3 для F4;
метрики исследовательской валидации и их окончательные определения остаются задачей D1.
Просадка и ошибка оценки считаются по снимкам с двумя сторонами стакана; отсутствие котировок
не интерполируется в цену. Доля пустой стороны взвешена длительностью интервалов снимков.
Execution rate — доля исполненного количества для заявок, поданных после прогрева, с учётом
их последующего исполнения. Дополнительные поля `retail_order_count`, `fund_order_count`
считают поданные после прогрева заявки, включая отказы; `*_active_agents` — число разных
подавших их инвесторов; `*_agent_count` — размер группы. Маркет-мейкеры исключены.
Активный участник здесь не обязательно совершил сделку. Эти поля доступны при наличии
дополнительной `population` metadata S; базовые диагностики работают и с обычным K3 без неё.
Notebook показывает активность, распределения и bootstrap по прогонам.
Показательные прогоны выбираются по ближайшей к медиане и 90-му перцентилю просадке.
30 сессий — короткий эксперимент; выводы ограничены этим горизонтом и выбранными параметрами.

## Результаты версии f4-v3

Повторно выполнены 3 пилотных и 450 основных прогонов с прежними конфигами и seeds.
Все 453 лога загружены через K3, диагностические CSV пересчитаны и сверены: деньги и акции
сохраняются, сумма исполнений заявок равна удвоенному объёму сделок, фонды имеют квоты 4/2/2.
Все шесть таблиц трёх полных пилотов точно совпали на Python и C++.

В каждом из 270 E1 есть заявки частных инвесторов. При h=0.3 и h=0.6 во всех прогонах
после прогрева заявки подавали все 72 частных инвестора; минимум по всей E1 — 48.
Средние числа заявок частных инвесторов при C=0.5: 2545 / 3088 / 3422 для h=0 / 0.3 / 0.6.
При C=0.8: 1846 / 2577 / 3422. Одинаковая активность при разных h не требуется:
минимальный лот устраняет техническое выключение от округления, а не все эффекты ликвидности.

При C=0.5 медианная просадка: **0.37% / 1.04% / 9.39%** для h=0 / 0.3 / 0.6.
Средняя парная разница h=0.6 минус h=0 — 10.17 процентного пункта;
95%-й bootstrap-интервал по 30 прогонам: [8.94; 11.42] п.п.
При C=0.2 и C=0.8 интервалы также положительны: [10.17; 12.97] и [8.54; 9.92] п.п.
При большом h просадка не растёт монотонно с C; прежний вывод об этом переносить нельзя.
Медианная доля времени с пустой стороной при C=0.5 — 0.32% при h=0 и 9.52% при h=0.6.

В E2 медианная просадка при замене трендовых сигналов шумом — 4.94%,
при отключении стадности — 0.37%, baseline — 9.39%.
В E3 при спредах 4/10/30 тиков медианы — 1.34% / 1.04% / 1.19%.
Эти результаты относятся к текущему правилу минимального лота и короткому горизонту.
При пустом стакане midpoint отсутствует; просадка считается только по наблюдаемым двухсторонним
котировкам. Большая доля отсутствующих котировок ограничивает сравнение просадок.

### Почему результаты f4-v2 заменены

В старой версии `floor(rho * abs(signal) * wealth / price)` давал ноль при финансово допустимой
покупке или продаже одной акции. В сохранённых логах seeds 1001–1003 после прогрева при C=0.5
среднее число заявок частных инвесторов падало с 1009 до 8 при h=0 → 0.6, число сделок —
с 757 до 114. При C=0.8 частные инвесторы не подавали заявок ни при одном h.
Поэтому числа `f4-v2`, включая 0.85% просадки при h=0.6, нельзя трактовать как отдельный эффект
имитации соседей. В `f4-v3` изменено только правило размера заявки; формула смешивания
`(1-h)*own + h*herd`, нулевые и просроченные публикации, капитал, seeds и стратегия фондов сохранены.
Сама формула по-прежнему одновременно ослабляет собственный сигнал и добавляет соседский;
эти каналы текущий E1 не разделяет. Минимальный лот также меняет эффективный размер риска
небольших портфелей. Чистая причинная оценка отдельного канала требует дополнительной ablation.

Результат 11.29% из `f4-v1` также остаётся устаревшим; близкое число в новой версии не восстанавливает
валидность прежнего расчёта. Старые логи не удалены и не смешиваются с новой выборкой.

Публичные контракты и их тесты не изменены.

## Целевая позиция и метрики D1 (12.11.2026)

**Метрики D1.** Сводка прогона одного актива (`experiments/diagnostics.py`, строка `summary.csv`) теперь
считается функциями D1 из `marketsim.metrics.stability` для актива 0: `max_drawdown`, `empty_side_fraction`,
`mean_spread_ticks`, `mean_depth5`, `execution_rate`, `valuation_error`, `quote_impact`, `volatility`
(между снимками) и `volatility_session` (по сессиям, `volatility(horizon=1)`), плюс прежние поля активности.
Поле `relative_valuation_error` заменено на `valuation_error` D1. На логах f4-v3 значения совпадают с прежними
диагностиками S (медианы просадки при C = 0,5 те же: 0,37% / 1,04% / 9,39%).

**Правило `position_sizing: target` в рынке одного актива.** То же, что в F6
(`docs/guides/f6_full_network.md`): цель инвестора — его начальное число акций × (1 + `position_tilt` × сигнал),
заявка закрывает разрыв, но не больше `rho` × портфель за решение; решение принимается, если |сигнал| >
`threshold` или разрыв больше `rebalance_band` × нейтральной позиции. Как и у `flow` в f4-v3, лот не меньше
одной акции, если разрыв — хотя бы целая акция. Без этого при C = 0,8 частный портфель (~4400 USD) никогда не
набирал одну акцию за решение, и частные инвесторы выпадали из рынка (в первом прогоне — 0 активных), то есть
стадность снова смешивалась бы с бездействием. Из ключей F5/F6 в режиме `single_asset` разрешены только
`position_sizing`, `position_tilt`, `rebalance_band`; по умолчанию (`flow`) логи F4 побайтно те же
(проверено на пилоте и первых прогонах E1–E3).

**Пересчёт E1–E3 обоими правилами** (906 прогонов, `runs/f4/v4/`, около 1 мин на 10 процессах):

| Медиана просадки, C = 0,5 | h = 0 | h = 0,3 | h = 0,6 |
|---|---|---|---|
| `flow` (f4-v3) | 0,37% | 1,04% | 9,39% |
| `target` | 0,39% | 0,87% | 3,56% |

| Парная разница h = 0,6 − h = 0 (95%-й интервал по 30 seeds) | C = 0,2 | C = 0,5 | C = 0,8 |
|---|---|---|---|
| просадка, `flow` | +11,6 п.п. [10,2; 13,0] | +10,2 [9,0; 11,4] | +9,2 [8,5; 9,9] |
| просадка, `target` | +3,4 [3,1; 3,8] | +3,1 [2,9; 3,4] | +2,0 [1,7; 2,3] |
| время с пустой стороной, `flow` | +5,7 [5,2; 6,2] | +9,2 [8,6; 9,8] | +14,5 [13,6; 15,4] |
| время с пустой стороной, `target` | +15,6 [14,7; 16,4] | +18,6 [17,7; 19,4] | +14,9 [14,1; 15,8] |

- **Стадность дестабилизирует рынок при обоих правилах**, но с целевой позицией просадка растёт в 3–5 раз
  меньше; при h = 0,6 `target` ниже `flow` на 7–8 п.п. при каждом C. Волатильность по сессиям и ошибка
  относительно оценок при h = 0,6 тоже выше, интервалы выше нуля.
- **С целевой позицией стадность чаще опустошает стакан** (+15…19 п.п. времени). Стадо, желающее одну сторону,
  снимает котировки мейкера и ждёт, а не гонится за ценой. Просадка считается только по двусторонним
  котировкам, поэтому её надо читать вместе с долей пустой стороны.
- **E2** (h = 0,6, C = 0,5, `target`): без стадности 0,39%, шум вместо трендовых 2,1%, базовый вариант 3,6%;
  базовый минус без стадности +3,1 п.п. [2,9; 3,4], минус без трендовых +1,5 [1,2; 1,8]. Главный канал —
  стадность, как и при `flow`.
- **E3** (h = 0,3, C = 0,5): спред мейкера 4 / 10 / 30 тиков — 0,93% / 0,87% / 1,34% при `target`
  (`flow`: 1,34% / 1,04% / 1,19%).
- Концентрация капитала при h = 0,6 просадку не увеличивает ни при одном правиле.
- Правило `target` добавлено после того, как результаты `flow` были известны (из F6), на тех же сетках и seeds:
  это пересчёт с исправленным правилом размера, а не независимая проверка на новых seeds.
