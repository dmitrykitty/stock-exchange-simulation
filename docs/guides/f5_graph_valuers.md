# F5: оценщики по графу и рынок нескольких акций

Точка входа та же, что в F4: `marketsim.sim.api.run(config, seed, out_dir)`. Если в конфиге `graph: single_asset`, работает рынок одного актива F4 (без изменений: логи и `run_id` совпадают с `main` бит в бит). Любое другое значение `graph` — имя графа K2 (`graph_chain`, `real_v1` или путь к каталогу), и запускается рынок F5: каждая компания графа — отдельный актив со своим стаканом. Лог — те же шесть таблиц K3; контракты K1–K4 и их тесты не изменены.

## Запуск

```bash
python -m marketsim.experiments.run configs/f5_pilot.yaml --out runs/f5/v1/pilot --workers 8
python -m marketsim.experiments.run configs/f5_e4.yaml --out runs/f5/v1/e4 --workers 8
python -m marketsim.experiments.run configs/f5_e4_followers.yaml --out runs/f5/v1/followers --workers 8
```

`notebooks/05_chain_wave.ipynb` читает эти каталоги и показывает волну, обвалы и отставание от эталона. Каталог `runs/` не коммитится.

## Что происходит в прогоне

| Элемент | Как сделано |
|---|---|
| Активы | компании графа в порядке `graph.companies()`; стартовая цена — `start_price` узла (USD → тики ×100) |
| Внешние сигналы | сценарий `external_<name>`; в нём должны быть все внешние узлы графа. Уровень меняется в начале сессии; если сценарий короче прогона, держится последний уровень |
| Эталон R | `reference_path(graph, external, mode="full")`, в тиках, постоянен внутри сессии; пишется в `valuations.reference` |
| Инвесторы | близорукие оценщики (`valuers_myopic`), сетевые (`valuers_network`), трендовые, шумовые; общий кошелёк на все акции |
| Внимание | `attention` — сколько акций торгует каждый инвестор (0 = все); набор случайный и фиксирован на прогон |
| Маркет-мейкеры | `market_makers_per_asset` на каждую акцию; мейкер держит акции только своего актива |
| Решение | при пробуждении агент снимает свои заявки, затем **по очереди** решает по каждой отслеживаемой акции: каждое решение видит стакан и кошелёк после предыдущего, порядок событий модели сохраняется |

### Оценка оценщика (главная формула, F5 раздел 2)

$$
\ln V_{a,i}(t) = \ln V_{a,i}(t') + \sum_{j} \hat w_{a,ij}\,\big[\ln P^{\text{obs}}_{a,j}(t) - \ln P^{\text{obs}}_{a,j}(t')\big]
$$

Сумма приращений между решениями «телескопируется», поэтому в коде считается равносильная форма $\ln V_{a,i}(t) = \ln V_{a,i}(0) + \sum_j \hat w_{a,ij}[\ln P^{\text{obs}}_{a,j}(t) - \ln P^{\text{obs}}_{a,j}(0)]$ — результат тот же, хранить состояние между решениями не нужно.

- **Родители:** близорукий берёт `w_direct` (только сырьё и индекс), сетевой — `w_full` (также компании). При `use_market_index: false` ребро от `sp500` игнорируют и агенты, и эталон.
- **Личная ошибка в весе:** $\hat w = w(1 + \eta)$, $\eta \sim N(0, \texttt{weight\_error\_std})$, своя для каждого агента, акции и родителя.
- **Запаздывание:** $P^{\text{obs}}(t) = P(t - d_a)$, $d_a \sim U[0, 2\cdot\texttt{observation\_delay}]$. Для сырья — уровень сессии, в которую попадает $t - d_a$. Для компании — середина спреда **на нашей бирже** (если стакан пуст с одной стороны — последняя сделка, затем стартовая цена): при $d_a = 0$ текущая, иначе из последнего снимка стакана не позже $t - d_a$.
- **Старт:** $V_{a,i}(0) = P_i(0)(1 + e)$, $e \sim N(0, \texttt{valuation\_std})$, обрезано до $[-0{,}9; 0{,}9]$.
- **Сигнал и заявка** — как в F4 (`gamma`, порог, минимальный лот, агрессивная/пассивная заявка); размер считается от **всего** портфеля: деньги + все акции по текущим ценам.
- **В логе** `valuations.v_mean`/`v_std` — по оценщикам, следящим за акцией, каждый по состоянию на своё последнее решение.

### Разная подверженность стадности

`herding.followers` — доля инвесторов, которые следуют за соседями; остальные решают сами ($h = 0$). У каждого «последователя» своё $h_a \sim N(h, \texttt{h\_std})$, обрезано до $[0; 1]$. По умолчанию (`followers: 1.0`, `h_std: 0`) у всех ровно $h$ — как в F4 (логи F4 не меняются). Работает и в F4, и в F5; значения $h_a$ пишутся в `meta.population.herding_h`. Сигнал соседей по акции считается только по соседям, которые эту акцию торгуют.

## Параметры (секция `agents`, свободная часть K4)

Новое для F5 (в F4 эти ключи запрещены, кроме `herding.followers` и `herding.h_std`):

| Ключ | По умолчанию | Смысл |
|---|---|---|
| `valuers_myopic`, `valuers_network` | 0 | число близоруких и сетевых оценщиков; `valuers` с графом не используется |
| `composition` | `custom` | `network` / `mixed` / `trend`: доли (близорукие, сетевые, трендовые, шумовые) = (15, 45, 20, 20)%, (30, 30, 20, 20)%, (35, 15, 30, 20)% от общего числа инвесторов |
| `attention` | 0 (все) | число акций у каждого инвестора |
| `observation_delay` | 0 | среднее запаздывание цен родителей, в сессиях |
| `weight_error_std` | 0 | разброс личной ошибки в весах |
| `herding.followers`, `herding.h_std` | 1.0, 0 | разная стадность |
| `total_shares` | — | в F5 — **на каждую акцию** |

`meta.json` дополнительно содержит хэши графа и сценария (`graph_sha256`, `external_sha256`, они входят в `run_id`), стартовые цены, внешние узлы, у населения — активы мейкеров, отслеживаемые акции, $h_a$ и запаздывания.

## Калибровка на пилоте (seeds 1–6; E4 — новые seeds 2001–2030)

**1. Ликвидность.** С одним мейкером на акцию (котировка 20 акций) после шока одна сторона стакана пустовала ~20% времени: 120 инвесторов «съедают» котировку быстрее, чем мейкер её обновляет.

| Мейкеры | Пустая сторона (худшая акция, медиана) |
|---|---|
| 1 × 20 акций | 21% |
| 1 × 50 | 12% |
| 2 × 20 | 9% |
| **2 × 50** | **2,6%** |

**2. Скорость передачи.** Когда после шока все оценщики хотят только покупать, продаёт им мейкер, а он ставит котировку вокруг текущей цены. С `inventory_skew_ticks = 0,02` (значение F4) цена растёт примерно на полспреда за обновление мейкера — около 1% за сессию, и «задержку» волны определял бы мейкер, а не агенты. Синтетическая цепочка x → A → B → C (веса 0,8, нефть +30%), доля эталона, пройденная ценой A к сессиям 4 / 8 / 17:

| `inventory_skew_ticks` | A | B к 17-й | C к 17-й |
|---|---|---|---|
| 0,02 | 6% / 32% / 102% | 32% | −29% |
| 0,2 | 56% / 144% / 101% | 76% | 81% |
| 0,5 | 110% / 97% / 103% | 109% | 164% |

С одними близорукими оценщиками B и C не двигаются (−4% и −10% эталона): без сетевых волна дальше первого звена не идёт.

**3. Устойчивость.** Доля прогонов, где какая-то акция упала больше чем на 25% от пика (2 мейкера × 50, `inventory_skew_ticks = 0,1`):

| Состав \ h | 0 | 0,2 | 0,3 | 0,4 | 0,5 |
|---|---|---|---|---|---|
| mixed | 0% | 0% | 0% | 8% | 58% |
| network | 0% | 0% | 8% | 8% | 42% |
| trend | 50% | 75% | 92% | 100% | 100% |

При сдвиге 0,2 обвалов больше (при h = 0,4 у mixed — 50%), поэтому выбран 0,1. Доля трендовых в составе `trend` снижена с 45% до 30%: с 45% обваливались все прогоны при любом h.

**Итог для E4:** 2 мейкера × 50 акций, `inventory_skew_ticks: 0,1`, сетка $h \in \{0; 0{,}2; 0{,}4\}$ (в F4 было 0 / 0,3 / 0,6: на цепочке с шоком $h \ge 0{,}5$ почти всегда приводит к обвалу — это результат, а не настройка).

**4. Колебания после шока — от трендовых агентов.** Смешанный состав, $h = 0$, стандартное отклонение $\ln(P/R)$ в сессиях 10–29:

| Вариант | COP | VLO |
|---|---|---|
| как в E4 | 2,6% | 4,3% |
| трендовые заменены шумовыми (`ablation: no_trend`) | 0,4% | 0,6% |
| `trend_lookback: 3` | 2,3% | 3,8% |
| медленный мейкер (0,02) | 3,2% | 5,1% |

Без трендовых цена догоняет эталон за ~2 сессии и успокаивается; с ними — затухающие «пузырь — обвал» с периодом ~5 сессий. Метрикам волны (D1) нужно мерить по окнам, а не по одной точке.

## Результаты (предварительные диагностики, не формальные метрики D1)

Все 738 прогонов (пилот 18, E4 540, E4-F 180): деньги и акции сохраняются, пустая сторона стакана — медиана 2,7% времени (худшая акция). Подробно — `notebooks/05_chain_wave.ipynb`.

**Обвалы** (E4, по среднедневным ценам; 60 прогонов в ячейке):

| Состав \ h | 0 | 0,2 | 0,4 |
|---|---|---|---|
| mixed | 0% | 0% | 7% |
| network | 0% | 2% | 13% |
| trend | 22% | 83% | 98% |

**Как цена догоняет эталон** (медиана по прогонам без обвала; 1 = цена сдвинулась ровно как R):

| Состав, h | COP сес. 5–6 | 7–9 | 10–14 | 25–29 | VLO сес. 5–6 | 7–9 | 10–14 | 25–29 |
|---|---|---|---|---|---|---|---|---|
| mixed, 0 | 0,48 | 1,31 | 0,97 | 0,99 | 0,38 | 1,54 | 0,85 | 0,98 |
| mixed, 0,2 | 0,48 | 1,38 | 0,95 | 1,00 | 0,36 | 1,67 | 0,77 | 0,99 |
| mixed, 0,4 | 0,43 | 1,50 | 0,93 | 1,01 | 0,33 | 1,72 | 0,58 | 0,98 |
| network, 0,2 | 0,47 | 1,36 | 0,96 | 0,99 | 0,27 | 1,72 | 0,71 | 1,02 |
| trend, 0,2 | 0,43 | 1,64 | 0,71 | 0,97 | — | — | — | — |

- Волна идёт **через сделки**: COP за две сессии проходит около половины пути, в сессиях 7–9 перелетает эталон на 30–60% и возвращается; VLO реагирует позже (у сетевого состава медленнее: сетевые оценщики ждут цену COP на бирже, а близорукие реагируют на нефть сразу) и перелетает сильнее — ошибка рынка COP передаётся дальше.
- Стадность увеличивает перелёт и среднее отклонение от эталона; при h = 0,4 сетевой состав обваливается чаще смешанного.
- DAL: эталонное движение всего ±0,8% (дешевеющая через НПЗ нефть помогает, прямое влияние нефти вредит), долю пройденного пути по нему читать нельзя — только абсолютное отклонение.

**Разная стадность (E4-F, mixed):**

| | средняя h | обвалы | отклонение VLO от R (медиана) |
|---|---|---|---|
| 25% последователей с h = 0,6 | 0,15 | 0% | 0,042 |
| 50% последователей с h = 0,6 | 0,30 | 0% | 0,052 |
| все с h = 0,6 | 0,60 | 98% | 0,120 |
| все с h = 0 / 0,2 / 0,4 (E4) | | 0% / 0% / 7% | 0,041 / 0,046 / 0,059 |

Рынок, где половина инвесторов сильно стадная, ведёт себя примерно как рынок с одинаковой средней стадностью; рушит рынок стадное большинство, а не меньшинство.

## Скорость

- Цепочка: 120 инвесторов × 3 акции × 30 сессий — ~7 с на прогон (Python-биржа); E4 (540 прогонов) — 7,2 мин на 10 процессах.
- Полный граф `real_v1` на `real_2024_2025` (заглядывание в F6, C++): 1000 инвесторов, каждый торгует 4 акциями, — ~1,0 с на сессию, то есть **~9 мин на прогон из 502 сессий**; 500 инвесторов — ~5 мин. Торгуются все 18 акций, пустая сторона стакана ≤ 3,5%, ресурсы сохраняются. Оценка по коротким прогонам (3–4 сессии); точную цифру даст пилот F6.

## Проверки

`tests/sim/test_network.py`: валидные таблицы и сохранение ресурсов по каждой акции; эталон в логе совпадает с `reference_path`; детерминизм; Python = C++ бит в бит (с вниманием, запаздыванием, ошибками весов и разной стадностью); волна проходит дальше первого звена только через сетевых оценщиков; запаздывание замедляет реакцию; ошибки весов дают разброс оценок; скрытый индекс игнорируется; внимание ограничивает торгуемые акции; «последователи» и разброс $h$; удержание последнего уровня сценария; отказ до создания вывода при ошибках конфига; пример K4 `configs/pilot.yaml` запускается. Логи и `run_id` F4 сверены с `main` (10 конфигураций × 2 биржи) — без изменений.

## Ограничения и открытые вопросы

- **Метрики волны** (полнота, задержка, перелёт, полупериод) — задача D1; здесь только диагностики. Учитывать колебания от трендовых и малое эталонное движение DAL.
- Калибровка мейкеров и сетки $h$ сделана на пилотных seeds и зависит от правила мейкера (котировка вокруг текущей цены, слабый сдвиг по позиции) и от насыщения сигнала оценщика при отклонении на `gamma` = 5%: дальше оценщик не давит сильнее, а тренд и стадность — продолжают.
- `total_shares` одинаков в штуках для всех акций; на `real_v1` с ценами от 33 до 346 USD это неравные по стоимости доли — для F6 распределять по стоимости.
- Для F6 ещё нужны ребалансировщики, stop-loss и решение о размере популяции (см. скорость).
