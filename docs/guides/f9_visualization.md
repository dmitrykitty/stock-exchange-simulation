# F9: воспроизведение прогона (replay) и живой режим

Первая часть F9: записанный прогон превращается в одну HTML-страницу. Её можно открыть в браузере без сервера и без интернета: plotly.js встроен в файл. Страница читает **только** лог прогона (K3), граф (K2) и, для сценариев на реальных датах, реальные цены закрытия для сравнения. Код симуляции она не импортирует (это проверяет тест).

## Запуск

```bash
pip install -e ".[viz]"                                   # plotly (нужен только для встраивания plotly.js)
python -m marketsim.viz.replay runs/<эксперимент>/<run_id> -o replay.html
```

Ключи:

| Ключ | Что делает |
|---|---|
| `-o FILE` | куда записать страницу (по умолчанию `<run_dir>/replay.html`) |
| `--no-real` | не добавлять реальные цены закрытия |
| `--cdn` | брать plotly.js из CDN (файл меньше на ~4,8 МБ, но нужен интернет) |

Страница весит 5–8 МБ. Длинные прогоны прореживаются до 5000 моментов на акцию (последний момент всегда сохраняется). Свечи считаются по **всем** сделкам сессии, поэтому прореживание на них не влияет.

## Что на странице

| Панель | Данные из лога | Что показывает |
|---|---|---|
| Граф | граф K2, `book`, `valuations`, события `session_start` | компании (круги) и внешние сигналы (квадраты); цвет — изменение цены с начала прогона или разрыв с эталоном R; светящееся кольцо и бегущие по стрелкам точки — цена этого узла движется прямо сейчас (изменение за последние полсессии, 3% = полная яркость). Так видно, как волна идёт по графу |
| Выбранная компания | `book`, `valuations` | цена рынка, эталон R, средняя оценка агентов; при включённом «real price» — реальная цена закрытия, которую агенты не видят |
| Свечи | `trades` | дневные свечи по всем сделкам сессии и объём |
| Ликвидность | `book` | спред между лучшими котировками (разрыв линии — одна сторона стакана пуста) и число акций на пяти лучших уровнях, bid вверх, ask вниз, за последние три сессии |
| Внешние сигналы | события `session_start` | нефть, газ, медь, золото, S&P 500, индекс к 100 на старте, логарифмическая шкала |
| Все компании | `book`, `valuations` | мини-графики цены и эталона по каждой компании, щелчок выбирает компанию |

Управление: ▶ / ❚❚ (пробел), шаг на один момент (← →) или на сессию (Shift + ← →), скорость в сессиях в секунду, ползунок времени. Переключатель цвета узлов: «Change since start» показывает саму волну, «Gap to reference R» — её запаздывание (насколько цена ещё не дошла до эталона). Тёмная тема включается по настройке системы.

## Готовые демонстрационные прогоны

Прогоны выбраны по правилу F7 (медиана, а не «самый красивый»):

| Файл | Прогон | Зачем |
|---|---|---|
| `oil_up.html` | `runs/f6/v1/oil_step`, нефть +20% на сессии 10, `mixed`, $h$ = 0,2, seed 101 | чистая волна: нефть → COP, EOG → VLO, MPC → авиакомпании и ODFL |
| `real_2024_2025.html` | `runs/f6/v1/e5_short`, ячейка `mixed`, $h$ = 0,2, seed 3006 (медиана ячейки по $\lvert\ln(P/R)\rvert$) | два года на реальных сигналах; 9 апреля 2025 (S&P 500 +9,5%) загорается весь граф |

Прогоны лежат в `runs/` (не в репозитории); страницы пересобираются командой выше за пару секунд.

## Живой режим

Вторая часть F9: симуляция идёт сейчас, а страница её меняет. Сеть, агенты и правила те же, что в F6; добавлены только управляющие события.

```bash
pip install -e ".[viz]"
python -m marketsim.viz.live                       # configs/f9_live.yaml, seed 101; страница откроется в браузере
```

Ключи:

| Ключ | Что делает |
|---|---|
| `--config FILE` | YAML эксперимента, запускается его `base` (по умолчанию `configs/f9_live.yaml`) |
| `--seed N` | seed прогона (по умолчанию первый из конфига) |
| `--sessions N` | сколько сессий максимум (по умолчанию из конфига, 250) |
| `--backend python\|cpp` | биржа; без собранного `lob_core` берётся Python, результат тот же |
| `--speed X` | скорость показа в сессиях в секунду при старте (0 — максимум) |
| `--port N` | порт (по умолчанию 8765), сервер слушает только `127.0.0.1` |
| `--out DIR` | куда писать лог (по умолчанию `runs/live`) |
| `--no-browser` | не открывать браузер |

`configs/f9_live.yaml` — откалиброванный рынок F6 (18 компаний `real_v1`, смесь `mixed`, $h$ = 0,2), но все внешние сигналы заморожены на уровне 2 января 2024 (сценарий `frozen_2024` из одной строки в `data/fixtures`). Поэтому новости на рынке — только те, что посылает докладчик. На Python-бирже прогон идёт примерно 1 сессию в секунду (измерено на ноутбуке команды), с `lob_core` быстрее.

### Как устроено

- Симуляция работает в **отдельном процессе** (`marketsim.sim.live.serve` вокруг `LiveSession`). Она делает шаг длиной `sample_dt` (0,05 сессии) обычным циклом событие за событием, без пакетной обработки агентов, и после каждого шага отдаёт кадр: цены, лучшие котировки, глубину, R, средние оценки, внешние сигналы, новые сделки.
- Сервер (`marketsim.viz.live`, только стандартная библиотека Python) передаёт кадры странице через server-sent events, а нажатия кнопок — обратно в процесс симуляции. Слой визуализации получает только сериализованные сообщения (кадры, ответы на управляющие события, подтверждения применения) и не трогает объекты симуляции.
- Сервер отвечает только запросам к своему адресу: заголовок `Host` должен быть `127.0.0.1:<порт>` или `localhost:<порт>`, `Origin` (если есть) — тот же адрес; POST принимается только с `Content-Type: application/json` и телом до 4 КБ. Так другая открытая в браузере страница не может управлять прогоном. Структура и типы управляющих событий проверяются до постановки в очередь, скорость — число от 0 до 1000.
- Шоки ограничены: вместе с уже применёнными и ожидающими шоками той же цели итоговый множитель внешнего уровня или оценок компании должен лежать в пределах от 1/1000 до 1000. Иначе событие отклоняется с ошибкой, прогон продолжается. Если симуляция всё же падает, страница и терминал получают сообщение об ошибке.
- Страница — те же панели, что в replay: граф с волной, выбранная компания (цена, R, средняя оценка, свечи), внешние сигналы, мини-графики всех компаний, плюс журнал управляющих событий.

### Кнопки и события лога

| Кнопка | Событие в `events` (`kind`) | Когда действует | Что меняет |
|---|---|---|---|
| **Oil +30% / −30%**, «Signal … Shock» | `shock_external`, payload `node`, `change`, `session`, `level_before`, `level_after` | с открытия следующей сессии | уровень внешнего сигнала умножается на $1 + x$ до конца прогона; эталон R пересчитывается; агенты с задержкой наблюдения видят новый уровень позже, как обычную новость |
| **Company news** (по умолчанию −20%) | `shock_valuation`, payload `asset`, `asset_index`, `change` | с текущего момента симуляции | оценка $V$ каждого оценщика этой компании умножается на $1 + x$ (новость о самой компании). R не меняется: это не сигнал графа. Сетевые оценщики компаний-потребителей реагируют уже на её цену |
| **Herding** (ползунок $h$) | `set_herding`, payload `h`, `followers`, `mean_h` | с текущего момента симуляции | $h$ каждого последователя становится новым (при `h_std` > 0 его личное значение сдвигается на $h_{new} - h$); ребалансировщики остаются с $h$ = 0 |
| Pause / Resume, Speed | — | — | только скорость показа; на результат не влияют и в лог не пишутся |
| **Stop & save log** | — | на ближайшей границе сессии | прогон заканчивается, лог пишется в `runs/live/<run_id>` |

Ctrl+C в терминале тоже дорабатывает текущую сессию и пишет лог: сигнал получает вся группа процессов, но процесс симуляции его игнорирует, а сервер просит его остановиться на границе сессии и ждёт записи лога K3.

В журнале «Control events» событие помечается applied только после подтверждения процесса симуляции. Граница обработки исключающая, поэтому событие со временем, равным моменту остановки, в лог не попадает и помечается «not applied (run ended)».

### Воспроизводимость

Управляющее событие получает **время симуляции**, а не время нажатия: внешний шок — открытие следующей сессии, остальные — момент, до которого симуляция уже дошла. Событие применяется перед всеми событиями очереди с этим временем или позже. Поэтому результат зависит только от seed и списка `(время, событие)`, а не от скорости показа или задержек браузера. Список пишется в `meta.controls`, конфиг — с фактическим числом сессий (`meta.config.n_sessions`), и

```bash
python -m marketsim.sim.live runs/live/<run_id>
```

заново прогоняет тот же конфиг с теми же событиями и сравнивает все шесть таблиц: `identical` значит, что лог совпал полностью, включая `run_id`. Это же проверяют тесты `tests/sim/test_live.py` (в том числе: остановка на сессии $S$ даёт тот же лог, что прогон с `n_sessions = S`; без событий живой лог совпадает с обычным `run`). Прогон 69 сессий на `real_v1` с тремя событиями, введёнными из браузера, воспроизводится за ~65 с.

Готовый лог открывается и как обычный replay: `python -m marketsim.viz.replay runs/live/<run_id> -o live.html`.

### Сценарий демонстрации на защите (3 минуты)

Перед защитой: `python -m marketsim.viz.live --no-browser`, страница открыта, прогон на паузе после 5–10 спокойных сессий, выбрана **VLO** (`http://127.0.0.1:8765/#asset=VLO`).

1. **0:00–0:30. Что на экране.** Слева граф: квадраты — внешние сигналы, круги — компании, стрелки — веса графа. Справа — Valero (НПЗ, второй шаг цепочки): цена рынка, пунктир — эталон R, оранжевая линия — средняя оценка агентов. Сейчас все сигналы заморожены: цены колеблются вокруг R, новостей нет. Нажать **Resume**.
2. **0:30–1:15. Нефть +30%.** Нажать **Oil +30%**. В строке под кнопками: «Oil +30% from the open of session N». С открытия сессии нефть становится синей, вокруг COP и EOG загораются кольца (+13…16%), по стрелкам бегут точки к VLO и MPC (+10…12%). На графике VLO эталон R прыгает сразу, а цена догоняет его за несколько сессий. Авиакомпании и ODFL лишь слегка краснеют (−1…−3%): в `real_v1` отрицательный вес нефти у них почти погашен положительными весами НПЗ, и их R почти не меняется — это видно, если навести мышь на DAL. В журнале «Control events» событие из pending становится applied.
3. **1:15–1:40. Запаздывание.** Переключить цвет на **Gap to reference R**: узлы, ещё не догнавшие R, видны сразу; через пару сессий граф снова нейтральный.
4. **1:40–2:10. Новость о компании.** В «Company news» уже стоит VLO: −20%, **Apply**. VLO падает примерно на 20%, R не меняется (новости нет в графе), разрыв с R виден в карточке и на мини-графике; сетевые оценщики авиакомпаний (VLO — родитель DAL) реагируют уже на цену VLO. Это и есть отличие «шок узла» от «шока сигнала».
5. **2:10–2:35. Стадность.** Перевести ползунок $h$ с 0,2 на 0,6: колебания становятся крупнее, цены чаще перелетают R. Вернуть 0,2.
6. **2:35–3:00. Лог.** **Stop & save log**: на странице появится путь к логу. В терминале: `python -m marketsim.sim.live runs/live/<run_id>` → `identical`. Все три действия — строки таблицы `events`, а прогон воспроизводится по seed и этим строкам (требование курса: параметры меняются во времени).

Если что-то пошло не так: Ctrl+C и перезапуск команды; seed тот же, первые сессии будут такими же.

## Чего пока нет

- Шага по отдельному событию (одна заявка, изменение стакана и портфелей): лог хранит снимки стакана с шагом `sample_dt`, а не каждый уровень после каждой заявки.
- Сравнения экспериментов (heatmaps, box plots): появятся после F7.
