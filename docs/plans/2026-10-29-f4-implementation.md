# План реализации F4

**Цель:** воспроизводимый рынок одного актива по `phases/F4_single_asset_market.md`.
**Архитектура:** последовательная очередь `(time, seq, event)`, агенты с отдельными генераторами,
текущий `Gateway`, один обработчик сделок, запись шести таблиц K3. Контракты K1–K4 неизменны.
**Технологии:** Python 3.11+, NumPy, pandas, PyArrow, PyYAML, pytest.

Работа выполняется в ветке `sim/single-asset-market`, в текущем checkout; дополнительные worktree
не создаются. Пользователь поручил сразу реализовать существующую спецификацию.

## Решения

- В F4 `graph: single_asset` означает синтетический рынок с ценой и тикером из `agents`.
  Это не файл графа K2. Другие графы отвергаются до реализации F5.
- `external: flat` загружается через API данных. Короткий постоянный fixture разрешено продолжать
  на нужное число сессий; изменяющиеся сценарии в F4 отвергаются.
- Денежные ресурсы и лимитные цены целые. Оценки и сигналы дробные. Середина нечётного спреда
  округляется вниз; лимитные покупки округляются вниз, продажи вверх.
- Отдельные случайные потоки: начальные оценки, знакомства, пробуждения и решения каждого агента.
- Стратегии и численность фондов не меняются при изменении концентрации. Целые остатки ресурсов
  распределяются детерминированно. Маркет-мейкеры финансируются отдельно.
- Перед решением агент снимает старые заявки; маркет-мейкер снимает обе котировки. Все GTD
  получают события истечения. Просроченные опубликованные сигналы соседей считаются нулевыми.
- K1 не кодирует ручную отмену и GTD expiry. В `orders.status` сохраняется последний K1-статус
  исполнения, `filled_qty` обновляется и для maker. Причина снятия и остаток пишутся в `events`
  (`order_cancelled`, `order_expired`, `run_end_cancelled`). Новые коды K1 не вводятся.
  Это ограничение существующих контрактов явно указывается в документации и metadata.
- Детерминизм означает идентичность всех таблиц и стабильного run_id. `started_at` и `wall_time_s`
  отражают реальное выполнение и не участвуют в сравнении. Существующий каталог не перезаписывается.
- Каждый прогон проверяет сохранение ресурсов, в debug-режиме — после каждого торгового события.
- Последовательный запуск сеток E0–E3 входит в F4; параллельный возобновляемый runner остаётся F7.

  неизвестные/невалидные параметры отвергаются. GREEN: реализация и полный pytest.
- [x] 2. Стратегии и стадность.

  сигнал после срока годности не влияет, заявки ограничены деньгами/акциями.

  Файлы: `sim/api.py`, `sim/engine.py`, `sim/recorder.py`, `tests/sim/test_run.py`.

  RED: CLI запускает ограниченную сетку, не теряет overrides, summary читается из K3.
- [x] 5. Пилот, полный pytest и ruff, независимый обзор, исправления и повторные проверки.
  Замерить скорость, торговую активность, пустые стороны и отклонение от средней оценки.
  Записать параметры и новые seeds до основных E1–E3; результаты хранить в `runs/`, не в Git.

## Журнал выполнения

- Ветка создана. Начальная установка из кэша невозможна: нет подходящих wheels NumPy.
  Устанавливаются зависимости из registry в локальное `.venv`.
- Исходный pytest: 56 passed, 37 skipped. RED примитивов: 18 failed (нет модулей),
  GREEN: 18 passed. RED стратегий: 6 failed (нет модулей), GREEN: 24 passed вместе с примитивами.
- RED интеграции: 12 failed (`NotImplementedError`), GREEN: 12 passed.
- Исправлен тест с недостаточным капиталом: по формуле q округлялся в ноль; тестовая сумма
  увеличена, производственное правило не менялось.
- Пилот 1–3: 662–1082 сделки после прогрева, пустая сторона 0.16–0.72%, ресурсы сохранены.
- C++ собран в локальном окружении для проверки идентичности таблиц с Python.
- Основная серия: E1 270, E2 90, E3 90; все 450 логов проверены через K3, инварианты и
  учёт обеих сторон сделки выполнены. Notebook исполнен, добавлены графики и bootstrap.
- Независимый обзор: блокирующих ошибок нет; найден неверный учёт времени при несовпадении
  границы прогрева с сеткой снимков. RED: 0 вместо 0.2, исправление — обрезка интервалов по
  границам, а не удаление предшествующего снимка. Конфиги основных экспериментов не затронуты.
- Дополнительно отвергаются чрезмерные спреды, отступы и inventory skew, вызывавшие overflow.
  Три теста сначала падали, затем прошли. Контрактные тесты не изменены.
- Финальная проверка: 137 passed, 7 skipped (данные и эталон D2), ruff чистый,
  notebook исполнен. Независимый повторный обзор подтвердил исправления и результаты.
- Формальные метрики D1 не подменяются диагностикой S; соответствующая часть M1 остаётся открытой.
