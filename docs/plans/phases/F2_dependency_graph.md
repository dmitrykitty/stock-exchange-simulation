## 0. Что такое граф и зачем он

Граф — это **знание агентов о том, что от чего зависит**. Ребро `parent → child` с весом $w$ значит: «если цена родителя изменилась на 1%, справедливая оценка ребёнка меняется на $w$%». Граф **не вычисляет цены**: агенты-оценщики используют его, чтобы пересчитывать свои оценки, когда видят движение цен родителей (см. `docs/model/model_description.md`, раздел 4.2).

- **Узлы:** внешние (сырьё: `wti`, `henry_hub`, `copper`, `gold`; индекс `sp500`; Brent и платина собираются в F1, но в граф не входят) и компании (18 тикеров из `companies.csv`).
- **Структура** (какие рёбра есть) — из экономики: таблица BEA «кто у кого покупает» + очевидные связи «сырьё → компании» + «индекс → каждая компания».
- **Веса** (насколько сильно) — из цен: регрессия дневных доходностей 2021–2023.
- **Два набора весов:** `w_direct` (родители только внешние) — для «близоруких» оценщиков; `w_full` (внешние + компании) — для «сетевых».

## 2. Шаг 1. Структура графа

### 2.1 Рёбра компания → компания из BEA

Правило: ребро `поставщик → покупатель` есть, если **отрасль покупателя тратит на продукцию отрасли поставщика не меньше порога** (по умолчанию 2%) своего выпуска:

$$
A_{j,i} \ge \text{threshold}, \qquad A_{j,i} = \frac{\text{покупки отрасли } i \text{ у отрасли } j}{\text{выпуск отрасли } i}
$$

Компании наследуют связи своих отраслей: если `A["324", "481"] = 0,129 ≥ 0,02`, то рёбра VLO → DAL, VLO → UAL, MPC → DAL, MPC → UAL.

```python
from marketsim.data import api

A = api.load_io_matrix(2023)
comp = api.load_companies()
rows = []
for _, sup in comp.iterrows():
    for _, cus in comp.iterrows():
        if sup.ticker == cus.ticker:
            continue
        share = A.loc[sup.bea_code, cus.bea_code]
        if share >= 0.02 and (sup.bea_code != cus.bea_code or A.loc[sup.bea_code, sup.bea_code] >= 0.02):
            rows.append((sup.ticker, cus.ticker, sup.bea_code, cus.bea_code, share))
```

**Что ожидать:** десятки кандидатов. Ручные рёбра без порога BEA (только с обоснованием): NVDA, AMD → GOOGL, META (AI-оборудование для AI-сервисов; NVDA → GOOGL +0,088, t = 4,2). Каждый надо **просмотреть руками**: оставить только осмысленные и написать обоснование (`justification` — обязательное поле). Реальные доли (2023): 211 → 324 = 0,508; 324 → 481 = 0,129; 211 → 22 = 0,027; 22 → 514 = 0,010 (ниже порога — значит, ребра энергетика → GOOGL/META не будет; это нормально и это результат).

### 2.3 Индекс → каждая компания

`sp500 → <каждая компания>`, `source = "index"`. Обязательно: без индекса веса между компаниями завышаются общим движением рынка.

## 3. Шаг 2. Веса: регрессии

Для каждой компании $i$ — регрессия дневных log-доходностей на доходности её родителей, период **2021-01-01 — 2023-12-31**:

$$
r_{i,t} = \alpha_i + \sum_{j \in \text{parents}(i)} w_{ij}\, r_{j,t} + \beta^{\text{mkt}}_i\, r^{\text{mkt}}_t + u_{i,t}
$$

- **`w_direct`**: родители — только внешние узлы (сырьё из 2.2 + `sp500`);
- **`w_full`**: внешние + компании-родители из 2.1.

Код (numpy, без дополнительных библиотек):

```python
import numpy as np

def ols(y, X):
    """y: Series; X: DataFrame of parents. Returns (coefficients, t-statistics, R^2) without the intercept."""
    Xm = np.column_stack([np.ones(len(X)), X.to_numpy()])
    b, *_ = np.linalg.lstsq(Xm, y.to_numpy(), rcond=None)
    resid = y.to_numpy() - Xm @ b
    s2 = resid @ resid / (len(y) - Xm.shape[1])
    se = np.sqrt(np.diag(s2 * np.linalg.inv(Xm.T @ Xm)))
    r2 = 1 - resid.var() / y.to_numpy().var()
    return dict(zip(X.columns, b[1:])), dict(zip(X.columns, b[1:] / se[1:])), r2

r = api.load_returns_daily().loc["2021-01-01":"2023-12-31"].dropna()
coef, t, r2 = ols(r["DAL"], r[["VLO", "wti", "sp500"]])
```

## 7. Шаг 6. Эталонная траектория `reference_path`

«Что было бы, если бы все агенты мгновенно и точно применили полные веса»:

$$
\ln R_i(t) - \ln R_i(0) = \sum_{j \in \text{parents}(i)} w_{ij}\,\big[\ln R_j(t) - \ln R_j(0)\big],
\qquad R_k(t) = X_k(t) \text{ для внешних узлов}
$$

Считать в топологическом порядке (от внешних узлов к дальним компаниям). Если в графе есть циклы — решать линейную систему $(I - W)\,\Delta\ln R = B\,\Delta\ln X$.

**Проверка:** `pytest tests/contracts/test_graph_contract.py::test_reference_path_follows_the_formula` — сейчас пропускается, после реализации должен пройти. Для цепочки и нефти +20%: COP $= 0{,}516 \ln 1{,}2$, VLO $= 0{,}701 \cdot \text{COP} + 0{,}069 \ln 1{,}2$, DAL $= 0{,}222 \cdot \text{VLO} - 0{,}139 \ln 1{,}2$ (в логарифмах).

## 9. Подвохи

- **Корреляция ≠ связь.** NEE → GOOGL даёт −0,10 (t = −3,2), но это скорее общий фактор процентных ставок, а не электричество. Поэтому структуру берём из экономики, а не из корреляций.
- **Веса зависят от набора родителей.** DAL на нефть: −0,04 без VLO и −0,14 с VLO. Это не ошибка: так и задумано два набора весов.
- **Одна компания — одна отрасль.** Exxon (добыча + переработка) не включён именно поэтому.
- **S&P 500 содержит наши компании** (NVDA, GOOGL, META — заметные доли). Это упрощение, его пишем в ограничения.
