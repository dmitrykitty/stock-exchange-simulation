# F5. Graph Valuers — оценщики по графу на цепочке из трёх акций

**Владельцы:** S + D2
**Срок:** неделя 5
**Зависит от:** F4 (рынок), F2 (формат графа, синтетическая цепочка, `reference_path`), F3 (несколько активов). **От неё зависит:** F6.

---

## 0. Цель

Агенты пересчитывают оценки **по графу**, и шок нефти проходит по цепочке `wti → COP → VLO → DAL` **через сделки**. На цепочке это видно и измеримо (эксперимент E4).

## 1. Интерфейсы

| Что | Где |
|---|---|
| Граф | `marketsim.graph.load_graph("graph_chain")` → `parents(child, mode)`; `mode="direct"` для близоруких, `"full"` для сетевых |
| Внешние сигналы | `marketsim.data.api.load_external("oil_shock")` (по сессиям) |
| Эталон для метрик и лога | `marketsim.graph.reference.reference_path(graph, external)` (D2) |
| Шлюз на 3 актива | `make_exchange(backend, n_assets=3)`, `Gateway` (K1) |
| Лог | таблица `valuations` в K3: средняя и разброс оценок + эталон |

## 2. Правило пересчёта оценки (главная формула проекта)

$$
\ln V_{a,i}(t) = \ln V_{a,i}(t') + \sum_{j \in N_a(i)} \hat w_{a,ij}\,\Big[\ln P^{\text{obs}}_{a,j}(t) - \ln P^{\text{obs}}_{a,j}(t')\Big]
$$

- $t'$ — прошлое решение агента; $N_a(i)$ — родители, которых агент знает: близорукий — внешние узлы (веса `w_direct`), сетевой — внешние и компании (веса `w_full`);
- $P^{\text{obs}}_{a,j}(t) = P_j(t - d_a)$ — цена родителя **с опозданием** $d_a$: для внешних узлов — значение сигнала текущей сессии, для компаний — **цена на нашей бирже** (середина спреда или последняя сделка; выбрать и записать);
- $\hat w_{a,ij} = w_{ij}(1 + \eta_{a,ij})$ — личная ошибка агента в весе;
- старт: $V_{a,i}(0) = P_i(0)(1 + e_a)$.

Реализация: кольцевой буфер цен каждого актива (снимки каждые `sample_dt`), чтобы получать цену «с опозданием»; оценки хранить в логарифмах.

## 3. Мультиактивность

- Общий кошелёк агента на все активы (шлюз уже так устроен).
- Агент торгует подмножеством активов (здесь — одним или двумя), но видит цены всех.
- Маркет-мейкер на каждый актив.

## 4. Эксперимент E4

Синтетический скачок нефти +20% (`oil_shock`) и −20% (`oil_shock_down`). Сетка: состав агентов (3 варианта: много сетевых оценщиков / смешанный / много трендовых) × $h$ (3) × направление шока (2) × 30 seeds = 540 прогонов. Реализовано в `configs/f5_e4.yaml`: $h \in \{0; 0{,}2; 0{,}4\}$ (на пилоте при $h \ge 0{,}5$ цепочка почти всегда обваливалась), seeds 2001–2030; дополнительно `configs/f5_e4_followers.yaml` — разная стадность.

## 5. Метрики (D1)

По каждому звену цепочки относительно эталона $R$: полнота передачи, задержка, перелёт, полупериод ошибки, усиление по цепочке (полнота на 3-м звене против 1-го). Определения и пример — `docs/model/explainer.md`, раздел 8.2.

## 6. Готово, когда

- [x] на цепочке видна волна: шок нефти доходит до DAL (`notebooks/05_chain_wave.ipynb`); **измерить** — метрики D1;
- [x] при 0% сетевых оценщиков волна дальше первого звена не проходит (тест на синтетической цепочке x → A → B → C: B и C сдвигаются на −4% и −10% эталона против 76% и 81% с сетевыми);
- [ ] полнота и задержка различаются между составами агентов — по диагностикам да (VLO у сетевого состава медленнее в первые сессии и сильнее перелетает), формально — после метрик D1;
- [x] таблица `valuations` в логе содержит эталон, и он совпадает с `reference_path` (тест).
