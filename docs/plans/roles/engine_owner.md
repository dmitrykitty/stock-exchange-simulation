# Роль O: движок биржи и шлюз

**Твои фазы:** [F3](../phases/F3_exchange_engine.md) (главная), F6 (скорость на 20 активах), F7 (параллельный runner), [F9](../phases/F9_visualization.md) (панель стакана, живой режим).
**Ты владеешь:** контрактом K1 (`src/marketsim/market/api.py`, `cpp/include/lob_core/`).
**Ты пользуешься:** K3 (лог — для панели стакана), K4 (поле `exchange_backend`).

## Что делать

| Неделя | Задачи | Результат |
|---|---|---|
| 1, дни 1–2 | GitHub, защита `main`, CI; прочитать `api.py`, F3 раздел 2, тесты | репозиторий готов к PR |
| 1, день 3 | **встреча с S: согласовать K1** | K1 заморожен |
| 1, дни 3–5 | `PyExchange`, затем `Gateway` | тесты контракта рынка и шлюза проходят → отдать S |
| 2 | C++: стакан одного актива, `submit`, `cancel`, `top`, `depth` | первые тесты проходят для `cpp` |
| 3 | C++: self-trade, ID, `submit_batch`, `last_trade`; дифференциальный тест | **M1**: C++ = эталон |
| 4 | C++ в симуляции (`exchange_backend: cpp`); бенчмарк; профиль вместе с S | **M2**: таблица скорости |
| 5–6 | оптимизация (батчи, буферы вместо списков), 18–20 активов | скорость приемлема для 270 прогонов |
| 7 | параллельный `ExperimentRunner` с S; бэкенд живого режима | прогоны идут параллельно |
| 8–9 | стабильность под нагрузкой; живой режим для защиты | демо работает |

## Правила

- Семантика — это тесты. Если тест кажется неправильным — это изменение контракта (PR, одобряют O и S), а не правка теста под код.
- C++ и Python-эталон должны давать **побитово одинаковые** результаты.
- Цены и деньги — только целые числа.
